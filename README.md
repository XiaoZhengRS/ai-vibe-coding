# 中转小科普——请守护你的钱袋子

由于市面上各类 API 聚合网关与模型原厂的限制，大模型的落地计费，大致受以下几个因素影响：

1. 充值倍率
2. 分组倍率
3. 模型倍率
4. 模型每百万 token 输入计价
5. 模型每百万 token 输出计价
6. 模型每百万 token 缓存输入（即大家常说的"缓存读"）计价
7. 模型每百万 token 缓存创建（即大家常说的"缓存写"）计价

## 一套看得懂的计费模板

在各个中转贩子的不断摸索下，有点良心的，都会采用一套让老板们看得懂的计费策略——毕竟好中转是为了让老板透明消费，而不是七拐八绕地藏起自己的真实落地价格。

这套计费是这样的：

1. 模型的输入、输出、缓存读、缓存写，全部对标原厂。例如 OpenAI 的 gpt-5.6-sol 模型：输入 5 刀/百万 token，输出 30 刀/百万 token，缓存读 0.5 刀/百万 token，缓存写同输入。
2. 充值倍率保证人民币与刀乐 1:1。（别问为啥不受国际汇率影响——中转的刀乐就是个游戏币，一个计账符号而已。）
3. 分组倍率自定义。

## 来算笔账

这样就很好算了。以 Matr 站 pro 分组为例：分组倍率 0.4，充值倍率 1:1，sol 模型输入 5 刀/百万 token、输出 30 刀/百万 token、缓存读 0.5 刀/百万 token。那么 sol 的综合定价就是：

- 输入：2 rmb/百万 token
- 缓存读：0.22 rmb/百万 token
- 输出：12 rmb/百万 token
- 长上下文（超过 256k）：输入与缓存读 ×2，输出 ×1.5（同样对标原厂）

另外，模型在正常使用过程中，大约 95% 的 token 消耗都在缓存读上。所以一个模型的最终价格贵不贵，盯着缓存读看就行了。

## 常见的做手脚姿势

综上所述，我们可以发现，能动手脚的地方还真不少：

1. 分组倍率调得很低，但充值倍率很高——7:1 充值，再给你调个 0.1 倍率。
2. 分组倍率低、充值倍率也低，但模型价格不对标原厂——例如 sol 模型直接拉到 50/300。
3. 上述全都正常，但偷偷给你塞 token——实际消耗 1 万，账单上写 2 万。
4. 上述全都正常，但在你跑 agent 长程任务时，故意冷不丁篡改你的缓存键，让缓存命中率奇低。
5. 上述全都正常，但拿便宜的模型映射成贵的模型卖给你。
6. 上述全都正常，价格也低廉得感人，但最低充值额度非常高——那多半是下药了，或者准备跑路了。
